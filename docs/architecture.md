# GraphRAG 系统架构

本项目已经完成数据 ETL、BGE/Milvus 向量检索、Neo4j 图谱检索、混合证据融合、BGE 重排、上下文预算、自然语言到受校验工具调用的智能体编排、FastAPI JSON/SSE 问答服务，以及 250 题纯向量/混合检索对照与 500 条本地大模型裁判评测。

```text
medical.json
├── documents.jsonl → chunks.jsonl → BGE → Milvus → 文本证据
└── triples.csv → Neo4j 类型化图谱 → 图谱证据
                                      ↓
用户问题 → 疾病实体/意图识别 → 严格工具调用（已完成）
                         ↓
          纯向量 / 图谱 / 混合路由与执行（已完成）
                         ↓
               混合融合 + 加权 RRF（已完成）
                                      ↓
                    BGE 重排 + 上下文预算（已完成）
                                      ↓
                     E1-En 证据上下文（已完成）
                                      ↓
                       证据约束回答（已完成）
                                      ↓
                       FastAPI JSON / SSE（已完成）
                                      ↓
                          检索 / 回答评测（已完成）
```

Milvus 回答“哪些文本与问题语义相近”；Neo4j 回答“已知疾病和哪些结构化医学实体有关”。第 5 阶段把两路结果归一为统一证据，使用加权倒数排名融合（RRF）合并排名，并按分块、图谱事实和同疾病精确文本去重。每条证据保留原始来源、来源名次、向量分数和融合贡献。第 6 阶段再用交叉编码器同时阅读问题与证据，输出独立的 `rerank_rank/rerank_score`；上下文构建器按估算词元数、条数和来源类型配额选择完整证据块，并生成可追溯引用。

接口中的混合双路调用通过 `asyncio.gather + asyncio.to_thread` 并发执行，避免同步等待 Milvus 完成后才开始 Neo4j。两路完成后仍按固定顺序执行融合、BGE 重排和上下文预算，保证结果可复盘。系统同时支持无需接口密钥的抽取式引用回答，以及通过 OpenAI 兼容接口连接 LM Studio/Qwen 的证据约束生成；两种后端都会校验 `[E1]` 等引用编号。

第 7 阶段能够从自然语言问题中识别精确疾病实体与查询意图，再决定调用向量检索、图谱检索或两者同时调用。图谱底层仍只接受结构化的 `disease_name + relations + limit`；混合检索会把同一个 `disease_name` 同步为 Milvus 的精确元数据过滤条件，并拒绝两路疾病不一致。若疾病缺失、同时出现多个疾病、参数越界或关系不在白名单，智能体会在数据库调用前停止。第 8 阶段通过 `MedicalChatService` 将计划、工具执行、证据和答案统一到一个请求 ID，并由 `/chat` 同时提供完整 JSON 与 SSE 两种传输方式。
